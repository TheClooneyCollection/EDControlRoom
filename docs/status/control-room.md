# Control Room Status
## Current
- Control Room now exposes `set_pid` and `set_hwnd` operator commands: input still defaults to the foreground app, bare `set_pid` / `set_hwnd` auto-target `EliteDangerous64.exe`, explicit numeric pid/hwnd values are accepted, `foreground` clears the override, startup logs show the current input target, the macOS `set_pid` path now falls back to full process-command matching for CrossOver/Wine launches, and the command bar/help text advertise the targeting controls.
- Control Room remote operator mode now keeps the existing local prompt and replay UX for `haul`, `haul route`, `haul search`, `dest`, `home`, and history replay/edit flows: `connect` intercepts those prompt-owning commands locally, reuses the same prompt helpers, replay browser, and trade-route picker behavior as embedded mode, preserves local prompt/replay state, in-progress command-bar drafts, client-local activity-log entries, and the current command-input caret position across server snapshot refreshes, uses observer-specific routine readiness so prompt-owning remote commands no longer fail on missing local bindings/controls, handles Enter on local prompt steps inside the observer instead of leaking blank fallback submissions to the server, guards the observer transport itself so stray duplicate `submit_input` calls for client-local verbs like `dest`, `haul`, `home`, `market`, `commands`, `help`, or `replay` are dropped before any websocket command reaches the headless server, and now also re-sorts merged remote plus preserved-local activity entries by timestamp on snapshot redraw so local prompt lines do not sink below newer remote routine/cancel lines. Picker-selected routes still load into a local haul prompt instead of asking the server to prefill it, the client still ignores server-owned prompt/replay widget state, and only finalized `command.dispatch_haul_loop` / `command.dispatch_destination` routine payloads go to the headless server while remote executed-history entries remain replay source data; the served schema/capabilities and retained server snapshot still prune remote-only `prompt_state`, `replay_browser`, replay-filter/browser-open fields, and replay/load-route command message types entirely, so the headless server only owns shared game/session state plus executable routine dispatch. Embedded/local Control Room prompt editing now also keeps live command-bar text in sync with active prompt prefill state, so periodic local snapshot refreshes stop reviving the original `haul search` parameter line after the operator edits it. `haul search [system]` still prefills one editable `key=value` line seeded from ignored local `haul_search.toml`, current ship system, current ship cargo capacity, and the `500 Ly` route-distance default, bootstrap now restores `cargo_capacity` from the latest journal `Loadout` so restart-time searches do not silently drop `cargo_capacity=` when only `Status.json` cargo count is fresh, `haul search url <inara-url>` still runs a pasted query directly, each list row now starts with compact per-hour profit like `[88.3m/h]`, the selected-route detail now folds endpoint `STATION DISTANCE` into the `From`/`To` line and still shows Inara `DISTANCE`, route distance, and `Per trip`/`Per hour` profit together in the visible panel, `artifacts/control-room-debug.log` now also traces remote `dest` prompt resolution, server-side destination dispatch receipt, and full routine exception tracebacks for live connect-mode debugging, `d` dispatches `dest` to the highlighted route's first-station system, and `Esc`/`q` dismisses the picker/browser.
- Market panel lock semantics are now aligned across embedded and `connect` modes: fresh market data keeps ingesting continuously, `market filter` / `market lock` / `market unlock` are client-local in `connect`, lock/unlock only freeze or unfreeze the displayed market panel instead of pausing the runtime-side `Market.json` / remote snapshot feed, and the served schema/protocol now prunes remote `market_filter_text` / `locked` snapshot ownership so the server streams only live market data while the client owns presentation state.
- Remote observer clients can now start on machines without a local Elite Dangerous journal path; both connect-mode startup and generic app mount paths now stay off the local-runtime journal guard so `control_room connect` reaches the remote snapshot and command surface cleanly, protocol-streamed activity log markup keeps the same Rich colors in `connect` mode instead of flattening to plain text, activity log rendering now uses each entry's stored protocol timestamp strictly so snapshot redraws and incremental remote appends keep their original times instead of repainting with the observer's local clock, and observer refresh merges now sort retained local prompt lines together with remote routine lines by timestamp instead of always appending local `dest`/prompt entries at the tail.
- Startup greeting TTS now waits for ship bootstrap so `title_mode = "commander_name"` uses the loaded CMDR name on first greeting, and immediate haul cancellation still emits its own dedicated spoken line instead of waiting for a route/session completion message that never applies to a partial run.
- Cargo manifest reads now retry briefly when `Status.json` reports cargo but `Cargo.json` is momentarily empty, and periodic status refresh now also reloads cargo details, so remote/local UIs recover the commodity breakdown and `sell`/haul resume avoid false "empty hold" decisions after server startup or transient manifest lag.
- Remote observer clients now retry dropped WebSocket sessions with exponential backoff, log reconnect delay and restoration messages locally, and request a fresh snapshot on reconnect so ping-timeout recovery can heal stale client state automatically.
- Cargo state now re-syncs from `Cargo.json` after `Cargo`, `MarketBuy`, and `MarketSell` events, so repeated `sell` flows stop relying on a drift-prone in-memory manifest while bootstrap still keeps `Status.json` as the startup cargo-count source.
- Replay-browser open/close, filter updates, selection movement, selected-entry execution/edit, default-haul toggling, and prompt/default Enter submissions now route through backend intent methods, while the status/haul/market panels render from backend snapshots instead of live app-owned state; the market panel now shows native `Buy`/`Sell` tabs above the existing scrollable commodity view so operators can switch sides without changing commands and long lists still keep a visible scrollbar under current Textual releases, the haul panel now shows live `Session` duration plus net session `Profit`, compact billion balances as `1b xxx.xxM CR`, the headless observer host republishes periodic haul refresh snapshots so remote elapsed/profit rows keep ticking between journal events, persisted session totals now survive relaunches, `new_session` / `clear` reset them without stopping an active haul, `stop` freezes the current session without clearing totals and resumes from the same totals on the next haul without counting stopped downtime, and `defaults/control_room.toml` plus `control_room.clear_session_on_launch` control whether startup restores or clears the saved session.
- Local mode now has an always-present `LocalControlRoomBackend` that owns snapshot/event subscription for the embedded app, while the old `_protocol_event_sink` hook remains only as a compatibility passthrough for external observers like `serve`.
- Observer transport now has shared-token auth plus `control_room connect <host>:<port>` over authenticated `GET /capabilities`/`GET /snapshot` and `WS /session`, with explicit capability metadata sourced from one shared protocol contract, a served JSON schema, a discoverable hosted browser probe URL, native clients and CLI probes preferring bearer-header websocket auth while browser probes stay on the advertised query-parameter path, permissive cross-origin HTTP discovery for future browser clients, live snapshots, activity and announcement streams, client-local TTS replay, bidirectional command envelopes, correlated errors, remote `Ctrl-C` prompt/routine interruption, and early client-side rejection of incompatible message/auth/discovery capability surfaces.
- Session snapshots are now personalized per connected client, the first authenticated client becomes `active_operator` by default, later clients can claim the role explicitly, and disconnect failover promotes the next connected client.
- Control Room now supports `home` / `home set`, repo-local `haul load [path]`, and replay/edit prefill for multi-step haul prompts; the config fallback path also creates repo-root `config.toml` instead of editing `config.example.toml`.
- Routine failures now surface as `Failed:` plus `Try:` guidance instead of raw internal-looking output, and activity-log retention plus the repo-local `artifacts/control-room.log` mirror are covered in tests.
## Caveats
- `control_room connect` still has one known live-only prompt bug: after `haul search <system>`, the observer can show the correct placeholder but an empty command bar instead of the expected serialized search params, despite local mode working and current harness coverage passing.
- The deepest remaining uncertainty is still live runtime behavior under routine-heavy real sessions, including the new targeted-input path; authentication also remains a shared LAN token rather than per-user or internet-ready identity.
