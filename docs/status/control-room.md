# Control Room Status
## Current
- Hub mode (`docs/user/hub.md`, since 2026-11-11, not yet tried live): with `[hub] url`/`token` set (`defaults/hub.toml`, empty = local), the server forwards `/api/eddn-routes` (ship and `haul_search.toml` inputs resolved locally by `resolve_route_params`), `/api/eddn-status` and the Inara haul search (websocket and `POST /api/haul-search`) to the hub, tagging answers `hub: <host>`, 502 / `hub_unreachable` when it is down. Visited markets go only to the hub (`HubMarketPusher`, thread `hub-markets`, `POST /api/markets`, newest wins; all recent markets at start and after a failed push). Peer health: thread `hub-heartbeat` pings `GET /api/hub-ping` every `heartbeat_s` (30 s) and logs `Hub <host> reachable/unreachable` on change; `edap.hub.HubStatus` (fed by heartbeat and pusher) backs `GET /api/hub-status` and the sidebar Hub chip (`web/hub-status.js`, every sidebar page). A non-200 ping (bad token) counts as unreachable; a refused push leaves reachability alone. Transport is `edap.hub.httpx_transport`, injected for tests.
- `POST /api/command` runs any Control Room command text over HTTP (same `submit_input` path as the web command box, token auth) and `POST /api/stop` cancels the running routine (`now` or `after_run`); 409 when refused because a routine runs. `submit_input` now returns whether it ran, from `RuntimeUIState.busy_refusals`, which every idle-only check bumps through `_refuse_busy`. Prompt-owning verbs (`haul`, `dest`, `home`, `market`) still do not run headless. Guide: `docs/user/command-api.md`. Not yet tried live.
- Web `/haul` shows an **Open in Inara** link for the last search (`query_url`, not kept across reload), and `pi2` is sent rounded up because Inara truncates it (17.2 acted as 17). The search also has a Surface stations select mapped to Inara `pi4` (checked against inara.cz 2026-11-10: `1` No, `2` Yes exclude Odyssey stations, `0` Yes with Odyssey stations), sent as `use_surface_stations` and saved to `haul_search.toml`; the server used to force `no`. `parse_surface_stations` in `edap/inara/trade_routes.py` is shared by TUI, server and web defaults. Inara results never set `from_manual_landing`/`to_manual_landing`, and should not: the flag means "cannot glide to the pad", not "on a planet".
- Web `/markets` lists the last 10 stations whose commodities market was opened (`control_room.recent_markets_file`, captured from `Market.json` by the TUI and the headless server, seeded at startup). It shows the full commodity table, sortable and hiding empty rows by default, and a Best deal panel at the top: deals rank by full-hold profit (hold capped by stock, so thin markets drop), each leg offers its top 3 to pick (buy, supply, sell, demand, profit/t, full hold), and the picked round trip goes to **Copy route** (the /haul paste box) or **Open in haul** (`/haul#route=<json>`, imported after the first hydrate so it becomes the server's selected route); backed by the pure `edap/market_compare.py` and `GET /api/recent-markets` / `/api/market-compare`. Every page's sidebar links to it and to `/routes`; on phones the sidebar is a scrolling nav row with only the ED mark (the shrunk brand name used to overlap the links). Not yet tried in a browser or a live session.
- Web `/controls` is a button board for single routines (undock, dock, jump, escape, boost, buy/sell/sell-all) plus pause/resume, stop after run/now, instant toggle and reload config/keymap, with a live activity feed; each panel shows `Idle` or `Busy: <routine>`, idle-only buttons disable while a routine runs, Flight has a big red `STOP NOW`, and instant mode is a switch. A Nav panel plots, travels and sets home; a Voice panel speaks free text or prefilled TTS presets through the host voice (`say`) and live-tunes Piper model, length, noise, noise W, sentence pause and volume (`voice set`), with Save writing `[tts.piper]` (`voice save`). Linked from the `/haul` and `/multi-haul` sidebars. Built on the existing `command.submit_input` and `command.cancel_active_routine` paths; not yet tried in a real browser.
- `reload_config` (TUI and web command box) re-reads `config.toml` without a restart: routine timings, haul/market settings and TTS wording apply from the next routine. Paths, input backend, timing jitter and server settings still need a restart; the Piper voice changes live through `voice set`. Refused while a routine runs; a broken file keeps the running config.
- `serve`/`lan`/`local` speak TTS on the server host by default (platform voice or `[tts.piper]`); `--no-tts` silences it, and a `connect` TUI on the same machine needs it to avoid double callouts. The haul web page can also speak in the browser (`web/speech.js`) for iPhone/Safari: per-device opt-in, one tap per load, only while the screen is awake.
- Plan 0008 is the active Control Room architecture target: one local-first `ControlRoomApp` composed with data sources, view models, view actions, and execution dependencies; `connect` now bootstraps that same app with remote data/execution dependencies, and `serve` / `lan` / `local` expose authenticated no-snapshot hydrate/web routes with an implicit `edcr` token only when `--token` is omitted. `lan` detection ranks RFC1918 candidates and skips VPN/WARP (`198.18/15`) and CGNAT (`100.64/10`) so it does not advertise unreachable tunnel addresses.
- Status, haul, market, and trade-route picker rendering now pass through explicit ViewModels; market/trade-route interactions use display-neutral ViewActions behind Textual adapters, `/` plus `/haul` preserve the two-way haul web UI and now include Travel Assist via `command.dispatch_travel`, while `/multi-haul` serves a separate shared-asset Spansh-style planner with ship-derived defaults, injected server/auth config, and authenticated websocket/session recovery.
- `connect` currently intercepts prompt-owning commands like `haul`, `haul route`, `haul search`, `dest`, `home`, `help`, `history`, and `market` locally, then sends finalized `command.dispatch_haul_loop` / `command.dispatch_destination` payloads to the headless server; structured `command.dispatch_travel` is server-first and available to TUI/web clients.
- Cargo and haul session state are journal-driven: cargo manifest reads retry around transient empty `Cargo.json`, market buy/sell resync cargo, persisted haul totals and selected-route expected trip profit survive relaunch unless configured otherwise, pause requests and station-boundary pauses log/TTS from the server runtime. Session stats cover one haul: pause and relaunch mid-haul freeze and resume them; stop (`session_active = false`) logs a `Haul session:` summary and keeps them on screen, and the next haul starts them from zero; `new_session` zeroes them mid-haul. Elapsed stays frozen after stop/completion and starts fresh on the next haul; local panels and remote hydrate share these durations plus expected/last-delta profit fields.
- Remote observer clients can start without a local Elite journal path and reconnect with exponential backoff; websocket recovery relies on server hydrate messages, while client shutdown state stays local, priority `Ctrl-C`/`Ctrl-D` bindings avoid command-input collisions, and remote-active `Ctrl-D` opens the detach prompt then exits the client on the next press without cancelling the server routine.
## Caveats
- Known live-only connect bug: after `haul search <system>`, the observer can show the correct placeholder but an empty command bar instead of the serialized search params.
- Routine-heavy live sessions still need validation, especially targeted input with `set_pid` / `set_hwnd` under CrossOver and Windows.
- Shared LAN token auth remains acceptable for current remote work; per-user or internet-facing identity is not implemented.
