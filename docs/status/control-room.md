- Plan 0015 hub command centre (branch `feat/hub-command-centre`): all 8 build steps done and released 2026-11-11. Live run with a Mac hub and a Windows peer: the peer found the hub over mDNS, hub pages drove it (haul, Stop now) and the hub voice and mute worked; a hub restart mid-haul was not exercised. User guide: `docs/user/hub.md`. `[hub] role` = `standalone` (default) | `hub` | `peer`, or `control_room.py hub` / `peer` (= `lan` with that role, `with_hub_role`; an empty `[hub] token` falls back to the page token); hub and standalone open the market SQLite store (`edcr/market_db.py`, also the one station facts store: EDDN, journal, Market.json, Ardent, newest wins), a peer never does; `[eddn]` only starts the listener (never on a peer). Hub pages pick a node in the sidebar (`web/nav.js`, per browser) and see and drive it: `?node=` relays the session, allowlisted reads and `command.*`/`POST /api/command`/`/api/stop` over the link (`edcr/hub/relay.py`; `node_unreachable`/502 when it drops). The peer runs those on one long-lived loop (`NodeLoop` in `server/app.py`), not `asyncio.run` per call, which waited for any routine it started and so held a hub page's stop until the routine ended. Central haul history (`[hub] runs_file`), runs record their ship, Best deal measured profit per hour per ship and window. Hub voice (`edcr/hub/voice.py`, `[hub] voice_file`): the node picked in the picker is voiced hub-wide (none picked: the hub's own game), played on Play on hub speakers and Play in this browser; Mute <node> sends a `voice_mute` frame (local: directly) so the node's `TTSAnnouncer` and broker (announcements marked `muted`, skipped by speech.js and `connect` TUIs; its pages show "muted" on the Hub chip and a note, from `muted` in `/api/hub-status`) stay quiet, only while it plays on the hub, unmuted on node change, nothing playing or link drop; `tts.disabled_messages` are no longer published (`render_announcement` returns None), so the hub and browser speech skip them too.
- Peer link (`edcr/hub/`): a peer dials the hub's `/api/peer-link` websocket with `[hub] token` (required on hub and every peer), says hello with a stable `node_id` (`<config dir>/.control_room_node_id`), pings every `heartbeat_s`, redials with backoff 1-30 s. Markets, station facts and haul runs go through a SQLite outbox (`[hub] outbox_file`) removed only on ack; searches, routes, status, Best deal facts and history are request/response frames (502 `hub_unreachable` when down). Discovery (`edcr/hub/discovery.py`): the hub advertises with `zeroconf`; a macOS peer browses with the system `dns-sd` tool (`dnssd_browse`, `run_until`; `lan_browse` picks by platform), Linux/Windows with `zeroconf`. The hub advertises `_edcr._tcp.local` (TXT role, id, name, version) on its `lan` bind address (detected LAN for `0.0.0.0`, never loopback); a peer without `url` browses, remembers the first hub that welcomes it in `<config dir>/.control_room_known_hub.json`, ignores and warns about other hubs, refuses a welcome with another id, and does not guess between two; delete the file to switch. Browser and advertiser are injected (fakes in `tests/test_hub_discovery.py`). Python's own mDNS socket received no multicast on a Mac (likely Local Network permission), hence `dns-sd`; a same-Mac live run (hub `serve --host 0.0.0.0`, peer without `url`) found the hub via `dns-sd`, dialled its LAN address and linked.
- `POST /api/command` runs any Control Room command text over HTTP (same `submit_input` path as the web command box, token auth) and `POST /api/stop` cancels the running routine (`now` or `after_run`); 409 when refused because a routine runs. `submit_input` now returns whether it ran, from `RuntimeUIState.busy_refusals`, which every idle-only check bumps through `_refuse_busy`.
