# Control Room Status
## Current
- Control Room now exposes `set_pid` and `set_hwnd` operator commands: input still defaults to the foreground app, bare `set_pid` / `set_hwnd` auto-target `EliteDangerous64.exe`, explicit numeric pid/hwnd values are accepted, `foreground` clears the override, startup logs show the current input target, the macOS `set_pid` path now falls back to full process-command matching for CrossOver/Wine launches, and the command bar/help text advertise the targeting controls.
- Control Room remote operator mode now keeps the existing local prompt and replay UX for `haul`, `haul route`, `haul search`, `dest`, `home`, and history replay/edit flows: `connect` intercepts those prompt-owning commands locally, reuses the same prompt helpers, replay browser, and trade-route picker behavior as embedded mode, preserves local prompt/replay state across server snapshot refreshes, loads picker-selected routes into a local haul prompt instead of asking the server to prefill it, ignores server-owned prompt/replay widget state, and only sends finalized `command.dispatch_haul_loop` / `command.dispatch_destination` routine payloads to the headless server while still consuming remote executed-history entries as replay source data; `haul search [system]` still prefills one editable `key=value` line seeded from ignored local `haul_search.toml`, current ship system, current ship cargo capacity, and the `500 Ly` route-distance default, bootstrap now restores `cargo_capacity` from the latest journal `Loadout` so restart-time searches do not silently drop `cargo_capacity=` when only `Status.json` cargo count is fresh, `haul search url <inara-url>` still runs a pasted query directly, each list row now starts with compact per-hour profit like `[88.3m/h]`, the selected-route detail now folds endpoint `STATION DISTANCE` into the `From`/`To` line and still shows Inara `DISTANCE`, route distance, and `Per trip`/`Per hour` profit together in the visible panel, `artifacts/control-room-debug.log` traces loaded route metrics plus the exact modal label/detail strings for route-picker investigations, `d` dispatches `dest` to the highlighted route's first-station system, and `Esc`/`q` dismisses the picker/browser.
- Remote observer clients can now start on machines without a local Elite Dangerous journal path; both connect-mode startup and generic app mount paths now stay off the local-runtime journal guard so `control_room connect` reaches the remote snapshot and command surface cleanly, and protocol-streamed activity log markup now keeps the same Rich colors in `connect` mode instead of flattening to plain text.
- Startup greeting TTS now waits for ship bootstrap so `title_mode = "commander_name"` uses the loaded CMDR name on first greeting, and immediate haul cancellation still emits its own dedicated spoken line instead of waiting for a route/session completion message that never applies to a partial run.
- Cargo manifest reads now retry briefly when `Status.json` reports cargo but `Cargo.json` is momentarily empty, and periodic status refresh now also reloads cargo details, so remote/local UIs recover the commodity breakdown and `sell`/haul resume avoid false "empty hold" decisions after server startup or transient manifest lag.
- Remote observer clients now retry dropped WebSocket sessions with exponential backoff, log reconnect delay and restoration messages locally, and request a fresh snapshot on reconnect so ping-timeout recovery can heal stale client state automatically.
- Cargo state now re-syncs from `Cargo.json` after `Cargo`, `MarketBuy`, and `MarketSell` events, so repeated `sell` flows stop relying on a drift-prone in-memory manifest while bootstrap still keeps `Status.json` as the startup cargo-count source.
- Replay-browser open/close, filter updates, selection movement, selected-entry execution/edit, default-haul toggling, and prompt/default Enter submissions now route through backend intent methods, while the status/haul/market panels render from backend snapshots instead of live app-owned state; the market panel now exposes a vertical scrollbar when long commodity lists overflow, the haul panel now shows live `Session` duration plus net session `Profit`, compact billion balances as `1b xxx.xxM CR`, the headless observer host republishes periodic haul refresh snapshots so remote elapsed/profit rows keep ticking between journal events, persisted session totals now survive relaunches, `new_session` / `clear` reset them without stopping an active haul, `stop` freezes the current session without clearing totals and resumes from the same totals on the next haul without counting stopped downtime, and `defaults/control_room.toml` plus `control_room.clear_session_on_launch` control whether startup restores or clears the saved session.
- Local mode now has an always-present `LocalControlRoomBackend` that owns snapshot/event subscription for the embedded app, while the old `_protocol_event_sink` hook remains only as a compatibility passthrough for external observers like `serve`.
- Observer transport now has shared-token auth plus `control_room connect <host>:<port>` over authenticated `GET /capabilities`/`GET /snapshot` and `WS /session`, with explicit capability metadata sourced from one shared protocol contract, a served JSON schema, a discoverable hosted browser probe URL, native clients and CLI probes preferring bearer-header websocket auth while browser probes stay on the advertised query-parameter path, permissive cross-origin HTTP discovery for future browser clients, live snapshots, activity and announcement streams, client-local TTS replay, bidirectional command envelopes, correlated errors, remote `Ctrl-C` prompt/routine interruption, and early client-side rejection of incompatible message/auth/discovery capability surfaces.
- Session snapshots are now personalized per connected client, the first authenticated client becomes `active_operator` by default, later clients can claim the role explicitly, and disconnect failover promotes the next connected client.
- Observer-mode server now runs through `ControlRoomEventSink`, a broker-retained headless host, and protocol-backed replay/prompt helpers; tests cover websocket failover, replay navigation, and destination prompts, while the browser/CLI probes in `docs/operators/control-room-remote.md` validate the advertised auth and discovery flow without launching the full TUI.
- Control Room now supports `home` / `home set`, repo-local `haul load [path]`, and replay/edit prefill for multi-step haul prompts; the config fallback path also creates repo-root `config.toml` instead of editing `config.example.toml`.
- Routine failures now surface as `Failed:` plus `Try:` guidance instead of raw internal-looking output, and activity-log retention plus the repo-local `artifacts/control-room.log` mirror are covered in tests.
## Caveats
- The deepest remaining uncertainty is still live runtime behavior under routine-heavy real sessions, including the new targeted-input path; authentication also remains a shared LAN token rather than per-user or internet-ready identity.
