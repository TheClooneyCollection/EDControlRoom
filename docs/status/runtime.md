# Runtime Status
## Current
- Linux/Steam Deck: input defaults to a `/dev/uinput` virtual keyboard (`[input.linux] backend`, xdotool still selectable). Verified live 2026-11-08 in Desktop Mode and Game Mode (gamescope) (Proton, paths auto-detected, repo at `~/EDControlRoom` on the Deck). The Deck's controller preset needed Mac-style keyboard binds via `tools/set_binding.py` (original in `Custom.4.2.binds.bak`).
- Control Room startup and `tools.check_bindings` now warn when resolved UI direction keyboard chords overlap galaxy-map camera button bindings (both slots, excluding axes). Warnings are advisory and JSON includes `warnings`; arrow-key secondaries remove WASD camera conflicts. Keyboard secondary modifiers now come only from that slot, never from the primary.
- Routine FSD engagement now checks Status.json hardpoints (jump command/CLI, shared haul/travel/spansh departure, and travel from supercruise), toggles `DeployHardpointToggle` only for confirmed deployment, polls up to `[controls.hardpoints].retract_timeout_seconds` (5s) per attempt, retries once, and returns Failed:/Try: if still deployed. Unreadable status is retried briefly then warns and continues per operator decision; landing gear/cargo scoop remain outside this guard.
- Runtime config now layers ignored local `config.toml` over shipped category defaults in `defaults/*.toml`; timing still flows through a shared config-backed sampler for human-facing delays, repeat gaps, command-launch waits, key holds, and typing cadence while non-human infrastructure timing like journal polling stays deterministic.
- The macOS input backend lazily builds its pid-targeted Quartz poster and now uses `kCGEventSourceStateCombinedSessionState`; native apps like Sublime can receive background typing through it, but CrossOver/Elite still cannot.
- macOS `set_pid` auto-detect now falls back from `ps ... comm` to the full `ps ... command` line, but ignores WatchDog-style launcher rows whose first Windows `.exe` is not the requested process.
- Input backends now keep a shared foreground-by-default target model across macOS, Windows, and Linux; macOS can switch to pid-targeted Quartz posting, Windows can switch to pid/hwnd-targeted window-message dispatch, and the default auto-detect filter is `EliteDangerous64.exe`.
- `Status.json` parsing currently matches the documented ship `Flags` set; the reference docs do not define auto-docking or auto-launch bits there, so docking-computer state still has to be inferred from journal/music events rather than the status snapshot.
- macOS with CrossOver is the primary validated runtime path; Windows has early real-world community validation.
## Caveats
- CrossOver/Elite background input works through the `wine_helper` input mode (C helper in the bottle, `set_input wine_helper`, managed launch). Verified live 2026-11-07 on the Test bottle (CrossOver Preview, ghostty in front): the galaxy map opened and closed with no macOS focus theft, no Alt side effects, and the console helper ran headless. `foreground` stays the default config. Verify with the journal `Music` event, not `Status.json` `GuiFocus`. A press sent while the galaxy map is loading is dropped, so verification sequences need a gap of about 8s. A long-lived server helper loses focus after Mac app switches (`focus_failed`); a child-process focus fallback (`child_focus` in helper.log) recovers it, with a 4s child deadline (its time is logged as `child_focus ms=N`), a 6s `request_timeout_s` and 2 focus attempts; a slow focus retries instead of aborting the burst. Ships as **beta**: Elite still gets Mac mouse moves in the background and a `WH_MOUSE_LL` hook can't block them under Wine (raw input and cursor bypass it), so players must keep the mouse off the game window during menu steps. The 100% CPU helper was a terminal Ctrl-C SIGINT reaching it (Wine then spins and can't exit); the managed launch now starts it in its own session. Win32 focus is required: `SendInput` from inside the bottle without making Elite the Win32 foreground does nothing (2026-11-07), and Elite ignores controllers in the background, so no-focus input and the virtual-gamepad route are ruled out. Activation made Elite grab and show the Mac cursor once with ghostty still in front (cause unverified).
- Windows background targeting currently uses `PostMessageW` against a resolved top-level window. The CrossOver `ControlSend` result suggests Elite ignores window messages, so this path is likely ineffective until it is validated live.
- The legacy CV-driven align loop is still not ported into the active runtime.
