# Haul Status
## Current
- Two-way haul runs are now persisted as append-only JSONL in `control_room.haul_runs_file` (default git-ignored `.control_room_haul_runs.jsonl`, untouched by `clear`): one row per run, `completed` or `aborted` (stop, clear, new haul over a stale run, restart, or a resumed mid-run remainder), with per-visit buys/sells, raw events, cost/revenue/profit, expected delta, top-ups, warning IDs, phase and reason; the in-progress run and unwritten rows live in `.control_room_state.json` until append+fsync succeeds, and `edap/haul_history.load_runs` skips torn lines and dedupes. One-sided loops (blank station 1 buy) are now tracked too. `stats [today|48h|week|month|all|since YYYY-MM-DD]` (control room, web via submit_input) and `tools/haul_stats.py [window] [--json] [--file]` summarize it in local-time windows (week from Monday 00:00): completed runs, aborted runs on their own line, an all-in total, and route/commodity breakdowns; profit/hour and expected vs actual are completed-only; an `All trading (journal)` block adds a read-only ledger from the Elite journals for the same window (buys/sells, trade profit, AvgPricePaid sell margin, commodity/station totals, observed balance change, coverage, rough other flows; `--journal-dir` overrides in the CLI). Next: `/api/haul-stats` and the web History panel.
- Two-way and multi-leg haul buys now top up a short buy (bought `MarketBuy.Count` < expected `min(free, stock, Balance // BuyPrice)` or requested amount) up to `controls.market.buy_top_up_max_attempts` times (default `3`, `0` disables), then warn and continue (the no-units, can't-afford and still-short warnings are also spoken via TTS); a top-up the balance can't cover one unit of is skipped with a warning, and a known zero MAX limit backs out without waiting for `MarketBuy`. The user's local `config.toml` runs the shorter buy hold (`0-99t` 3.0s, `100t+` flat 4.5s; manual time to max at 1137t is ~3s).
- Carrier launch handoff now treats `Music` `Exploration` as manual launch control resumed after `Undocked` from `Stronghold Carrier` or `Fleet Carrier`, so two-way haul can continue into mass-lock escape/boost without waiting for `NoTrack` on that carrier-specific path.
- `haul search [system]` now treats `home` as the saved `control_room.home_system`, defaults from local ignored search config, accepts `max_station_distance_ls=any`, shows compact profit/distance detail, restores cargo capacity from latest journal `Loadout`, maps live Inara aliases, lets Enter load the highlighted route, `d` set `dest` to the first station system, `t` start travel to that station, `haul start` run the selected/saved route, and keeps `connect` search/results local until a structured route/destination/travel dispatch is submitted.
- Two-way haul phase/cargo matching now normalizes raw Elite commodity names like `$palladium_name;`, treats an empty or partial hold in a configured buy station's system as return-to-buy (supercruise, or normal space right after `Undocked`/docking request/station drop there; normal space elsewhere errors asking for supercruise instead of departing empty), docks straight from normal space after `Undocked` from the destination, does not count that initial return transit as an iteration, aborts buy before market input when cargo details are stale, and when known non-haul cargo is loaded announces the conflict, announces sell-all recovery, sells all sellable cargo, then retries the intended buy.
- Two-way `haul` loads ignored repo-root `haul.toml` by default via `haul load [path]`; the tracked profile shape lives in `defaults/haul.toml`, and the default haul docking timeout is now `1200s`.
- Market buy/sell quantity restore is now configurable: buy `MAX` defaults to `0-99t = 3.0s`, `100-300t = 5.0s`, then a `301t+` log curve that hits about `8.0s` at `800t`, with a `20.0s` global hold cap; sell `MAX` still restores quantity with configurable rapid `UI_Right` taps instead of a long hold. Sell routines also merge the hidden-cargo subset from `Cargo.json` into the demand-sorted `Market.json` sell list so hidden commodities no longer misindex sale rows.
- Two-way haul prompt/dispatch now records per-destination `on land` flags plus selected-route expected trip profit; web Haul v1 keeps `/haul` route search/start plus websocket search/select/destination/start/stop/pause/resume/stat commands intact, shows profit per trip plus per-station supply/demand sublines in results, exposes `min_supply`/`min_demand` filter inputs that persist into `haul_search.toml`, and compares completed run profit against the planned route with log/TTS, while `/multi-haul` remains a separate Spansh-style UI-only planner with ship-derived defaults and `command.dispatch_multi_leg_haul`.
- Two-way/multi-leg haul now retry galaxy-map route setting twice, TTS/log an unconfirmed-route warning, skip automatic FSD engage when route confirmation fails so the pilot can set the route manually, still skip galaxy-map setup for same-system station pairs, and still ignore intermediate `FSDJump` arrivals in multi-jump routes.
- Two-way `haul` now accepts one-sided loops: station 1 or station 2 buy cargo may be blank as long as the other side is configured, and the routine skips the missing buy/sell leg cleanly during prompt flow, launch, and resume detection.
- Two-way and multi-leg haul transit now announce the next station immediately after hyperspace arrival before opening the nav panel, and abort/TTS `haul_aborted` instead of requesting docking if an `Interdicted` event precedes the transit `SupercruiseExit`.
- Shared station transit mechanics now live in neutral `edap.routines.transit` helpers reused by two-way haul, multi-leg haul, and `travel`; haul cargo/runtime support remains in `edap.routines.haul_support`, and two-way `haul` remains the primary operator path while standalone `multi_leg_haul` / `mult` handles finite external JSON or Spansh-driven routes.
## Caveats
- Orbital station automation now treats pad-full `DockingDenied` reasons like `NoSpace` as transient hold-and-retry cases; other denial reasons still use the generic short retry path until live journals justify stricter classification, and `on land` still only hands off for manual landing instead of automating settlement trading screens.
- One-sided haul loops still need live validation to confirm station-side UI timing and resume behavior when a station intentionally has no configured buy cargo.
- Multi-leg flow still needs live validation for repeated stations, consecutive trades, final-leg completion semantics, and external routes that mark surface destinations with `on_land`; the new local-observer Inara search path still needs live operator validation for route-to-haul handoff in `connect` mode.
