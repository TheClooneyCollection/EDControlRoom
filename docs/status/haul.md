# Haul Status
## Current
- Carrier launch handoff now treats `Music` `Exploration` as manual launch control resumed after `Undocked` from `Stronghold Carrier` or `Fleet Carrier`, so two-way haul can continue into mass-lock escape/boost without waiting for `NoTrack` on that carrier-specific path.
- `haul search [system]` now treats `home` as the saved `control_room.home_system`, defaults from `defaults/haul_search.toml` with local ignored `haul_search.toml` overrides, including `max_route_distance_ly=500`; it accepts `max_station_distance_ls=any` in the editable Inara search line, normalizes it to Inara's `pi9=0` query value, maps pasted `pi9=0` trade-route URLs back to `any`, prefixes each route row with compact per-hour profit like `[88.3m/h]`, shows both per-endpoint `STATION DISTANCE` values in the endpoint row plus Inara `DISTANCE` and route distance in the selected-route detail and compact route label so `Per trip` / `Per hour` stay visible, restores `cargo_capacity` from the latest journal `Loadout` during Control Room bootstrap so restart-time searches still send total hold size to Inara instead of dropping `cargo_capacity=` when only live cargo count is known, maps live Inara profit aliases like `PROFIT PER LOAD` / `PROFIT/HOUR` back onto trip/hour metrics, lets Enter load the highlighted route into the haul prompt, `d` set `dest` to the highlighted route's first-system endpoint, `Esc`/`q` dismiss the picker, still parses live cards where both endpoint headers appear before the trade details by reading `BUY` commodity rows separately from `BUY PRICE` metrics before prefilling the haul prompt, and now keeps `control_room connect` haul search/results entirely local to the observer client so only the chosen route or destination is submitted to the remote host.
- Two-way haul phase/cargo matching now normalizes raw Elite commodity names like `$palladium_name;`, treats empty-hold supercruise in a configured buy station's system as return-to-buy, aborts buy before market input when cargo details are stale or known non-haul cargo is already loaded, and logs/TTS the appropriate stale-cargo or haul-aborted warning.
- Two-way `haul` loads ignored repo-root `haul.toml` by default via `haul load [path]`; the tracked profile shape lives in `defaults/haul.toml`, and the default haul docking timeout is now `1200s`.
- Market buy/sell quantity restore is now configurable: buy `MAX` defaults to `0-99t = 3.0s`, `100-300t = 5.0s`, then a `301t+` log curve that hits about `8.0s` at `800t`, with a `20.0s` global hold cap; sell `MAX` still restores quantity with configurable rapid `UI_Right` taps instead of a long hold.
- Two-way haul prompt/dispatch now records per-destination `on land` flags; web Haul v1 keeps the existing `/haul` two-way route search/start UI and websocket search/select/destination/start/stop/pause/resume/stat commands intact, with route-distance search as an editable field offering INARA-style `10 Ly` through `1,000 Ly` defaults, while separate `/multi-haul` reuses shared CSS for a Spansh-style UI-only planner with ship-derived defaults and a dedicated client-side `command.dispatch_multi_leg_haul` path for future backend work.
- Two-way/multi-leg haul now retry galaxy-map route setting twice, TTS/log an unconfirmed-route warning, skip automatic FSD engage when route confirmation fails so the pilot can set the route manually, still skip galaxy-map setup for same-system station pairs, and still ignore intermediate `FSDJump` arrivals in multi-jump routes.
- Haul prompt resume/edit now prefills the command input with the saved station names, systems, cargo legs, and timing values, and deleting a prefilled cargo/station field now leaves it truly blank instead of silently restoring saved text.
- Two-way `haul` now accepts one-sided loops: station 1 or station 2 buy cargo may be blank as long as the other side is configured, and the routine skips the missing buy/sell leg cleanly during prompt flow, launch, and resume detection.
- Two-way and multi-leg haul transit now announce the next station immediately after hyperspace arrival before opening the nav panel, and abort/TTS `haul_aborted` instead of requesting docking if an `Interdicted` event precedes the transit `SupercruiseExit`.
- Market sell routines now merge the hidden-cargo subset from `Cargo.json` back into the demand-sorted `Market.json` sell list so hidden commodities no longer misindex later sale rows.
- Shared two-way/multi-leg haul mechanics now live in `edap.routines.haul_support`, route entrypoints take grouped `HaulRuntime` plus route/definition objects instead of long timing/config signatures, and two-way `haul` remains the primary operator path while standalone `multi_leg_haul` / `mult` handles finite external JSON or Spansh-driven routes with live journal/cargo/market resume.
## Caveats
- Orbital station automation now treats pad-full `DockingDenied` reasons like `NoSpace` as transient hold-and-retry cases; other denial reasons still use the generic short retry path until live journals justify stricter classification, and `on land` still only hands off for manual landing instead of automating settlement trading screens.
- One-sided haul loops still need live validation to confirm station-side UI timing and resume behavior when a station intentionally has no configured buy cargo.
- Multi-leg flow still needs live validation for repeated stations, consecutive trades, final-leg completion semantics, and external routes that mark surface destinations with `on_land`; the new local-observer Inara search path still needs live operator validation for route-to-haul handoff in `connect` mode.
