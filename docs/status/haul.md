# Haul Status
## Current
- The per-station `on_land` flag is renamed `manual_landing` (handoff after `SupercruiseExit`, only for stations you cannot glide close to; planetary ports dock automatically without it, e.g. Chauhan Dock 2026-11-10). Old `on_land` / `from_on_land` / `to_on_land` names still load from `haul.toml`, saved state, pasted and multi-leg JSON, and the travel payload; `/routes` Copy always leaves it off.
- Market buy/sell station check now re-navigates into the commodities market on each of its 3 attempts (UI_Back x4, station services, market) instead of only re-reading `Market.json`. Live 2026-11-09 at Melroy Gateway (Coriolis) the open-market presses ~6s after `Docked` were lost (station services opened, no `Market` event), so all re-reads saw the previous station; journals show this on 4 of 24 Melroy dockings. Haul market buys/sells now pass `controls.market.nav_delay_seconds`; before 2026-11-09 they ignored it and used 0.1s, so the Deck's 0.2s setting never reached Voltaire Silver (row 36) buys.
- Undock clear-of-station now accepts `NoTrack`, `ReceiveText` `$STATION_NoFireZone_exited;` (combat music replaces `NoTrack`) or, from `Stronghold Carrier`/`Fleet Carrier`, `Music` `Exploration`. Under attack after `Undocked` (`UnderAttack` Target `You`, shields down, or player `HullDamage`) it TTS-warns `under_attack`, then on damage, a clear cue, or 40s after undock boosts out of mass lock, presses the optional `Supercruise` binding (Deck keymap `F8`, falls back to `HyperSuperCombination`), and on `SupercruiseEntry` TTS-asks the pilot to align and jump; haul then continues from arrival events. Standalone `undock` only warns and stops. Docking (request/grant and `Docked` waits) only TTS-warns `under_attack` once and keeps docking. Seen live 2026-11-08 at Voltaire Terminal (Powerplay security), which killed the ship once; the escape path still needs live validation.
- Two-way haul runs are now persisted as append-only JSONL in `control_room.haul_runs_file` (default git-ignored `.control_room_haul_runs.jsonl`, untouched by `clear`): one row per run, `completed` or `aborted` (stop, clear, new haul over a stale run, restart, or a resumed mid-run remainder), with per-visit buys/sells, raw events, cost/revenue/profit, expected delta, top-ups, warning IDs, phase and reason; the in-progress run and unwritten rows live in `.control_room_state.json` until append+fsync succeeds, and `edap/haul_history.load_runs` skips torn lines and dedupes. One-sided loops (blank station 1 buy) are now tracked too. `stats [today|48h|week|month|all|since YYYY-MM-DD]` (control room, web via submit_input) and `tools/haul_stats.py [window] [--json] [--file]` summarize it in local-time windows (week from Monday 00:00): completed runs, aborted runs on their own line, an all-in total, and route/commodity breakdowns; profit/hour and expected vs actual are completed-only, while since 2026-11-10 an aborted run's realized trades (stop, new haul, clear, restart, or a resumed run ending on a station 1 sale) stay in the session profit instead of vanishing; an `All trading (journal)` block adds a read-only ledger from the Elite journals for the same window (buys/sells, trade profit, AvgPricePaid sell margin, commodity/station totals, observed balance change, coverage, rough other flows; `--journal-dir` overrides in the CLI). `GET /api/haul-stats?window=` (auth like other `/api/*`, 400 on a bad window, `journal` null when unavailable) feeds a web Haul v1 History panel (Today/48h/Week/Month/All), and the TUI HAUL panel adds `Today +X (n runs)` from persisted rows (`Today unavailable` in connect mode). The file was backfilled with 26 rows (`source: journal_backfill`) for 2026-11-05..07 up to cutoff `2026-11-07T11:19:51Z`; hauls between that cutoff and the first restart with tracking are in neither.
- Two-way and multi-leg haul buys now top up a short buy (bought `MarketBuy.Count` < expected `min(free, stock, Balance // BuyPrice)` or requested amount) up to `controls.market.buy_top_up_max_attempts` times (default `3`, `0` disables), then warn and continue (the no-units, can't-afford and still-short warnings are also spoken via TTS); a top-up the balance can't cover one unit of is skipped with a warning, and a known zero MAX limit backs out without waiting for `MarketBuy`. The user's local `config.toml` runs the shorter buy hold (`0-99t` 3.0s, `100t+` flat 4.5s; manual time to max at 1137t is ~3s).
- `haul search [system]` now treats `home` as the saved `control_room.home_system`, defaults from local ignored search config, accepts `max_station_distance_ls=any`, shows compact profit/distance detail, restores cargo capacity from latest journal `Loadout`, maps live Inara aliases, lets Enter load the highlighted route, `d` set `dest` to the first station system, `t` start travel to that station, `haul start` run the selected/saved route, and keeps `connect` search/results local until a structured route/destination/travel dispatch is submitted.
- Two-way haul phase/cargo matching now normalizes raw Elite commodity names like `$palladium_name;`, treats an empty or partial hold in a configured buy station's system as return-to-buy (supercruise, or normal space right after `Undocked`/docking request/station drop there; normal space elsewhere errors asking for supercruise instead of departing empty), docks straight from normal space after `Undocked` from the destination, does not count that initial return transit as an iteration, aborts buy before market input when cargo details are stale, and when known non-haul cargo is loaded announces the conflict, announces sell-all recovery, sells all sellable cargo, then retries the intended buy.
- Two-way `haul` loads ignored repo-root `haul.toml` by default via `haul load [path]`; the tracked profile shape lives in `defaults/haul.toml`, and the default haul docking timeout is now `1200s`.
- Market buy/sell quantity restore is now configurable: buy `MAX` defaults to `0-99t = 3.0s`, `100-300t = 5.0s`, then a `301t+` log curve that hits about `8.0s` at `800t`, with a `20.0s` global hold cap; sell `MAX` still restores quantity with configurable rapid `UI_Right` taps instead of a long hold. Sell routines also merge the hidden-cargo subset from `Cargo.json` into the demand-sorted `Market.json` sell list so hidden commodities no longer misindex sale rows.
- Two-way haul prompt/dispatch now records per-destination `manual_landing` flags plus selected-route expected trip profit; web Haul v1 keeps `/haul` route search/start plus websocket search/select/destination/start/stop/pause/resume/stat commands intact, shows profit per trip plus per-station supply/demand sublines in results, has a `Copy / paste route` box that copies the selected route as JSON and imports a pasted one (selected and persisted through `command.select_trade_route`) so a host without Playwright, like the Steam Deck, can run a route searched on another Control Room, exposes `min_supply`/`min_demand` filter inputs that persist into `haul_search.toml`, and compares completed run profit against the planned route with log/TTS, while `/multi-haul` remains a separate Spansh-style UI-only planner with ship-derived defaults and `command.dispatch_multi_leg_haul`.
- Two-way/multi-leg haul now retry galaxy-map route setting twice, TTS/log an unconfirmed-route warning, skip automatic FSD engage when route confirmation fails so the pilot can set the route manually, still skip galaxy-map setup for same-system station pairs, and still ignore intermediate `FSDJump` arrivals in multi-jump routes.
## Caveats
- Orbital station automation now treats pad-full `DockingDenied` reasons like `NoSpace` as transient hold-and-retry cases; other denial reasons still use the generic short retry path until live journals justify stricter classification, and `on land` stations are landed manually: two-way and multi-leg haul TTS `manual_landing` after the drop, wait for `Docked` (dock timeout) and then trade and continue; before 2026-11-10 haul exited there, so the run was recorded aborted and `resume` found no haul. Standalone `travel`/Spansh routes still end at the handoff.
- One-sided haul loops still need live validation to confirm station-side UI timing and resume behavior when a station intentionally has no configured buy cargo.
- Multi-leg flow still needs live validation for repeated stations, consecutive trades, final-leg completion semantics, and external routes that set `manual_landing`; the new local-observer Inara search path still needs live operator validation for route-to-haul handoff in `connect` mode.
